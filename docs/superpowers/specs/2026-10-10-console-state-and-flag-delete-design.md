# 控制台状态、Flag Key 选择与 Flag 删除

日期：2026-10-10。基线：a0b62bf / v1.0.0。状态：用户已确认设计（“确认，进行修改”）；实现、回归测试、独立审查及真实浏览器验证完成。

## 用户提出的三个问题

1. 控制台切到 Flag 列表再返回时应保留已有状态。
2. 评估输入的 Flag Key 应支持自定义输入，也能直接选择已有 Flag Key。
3. Flag 列表应支持删除整个 Flag。

## 现状与原因

- App 的 Routes 离开 /console 时卸载 ConsolePage。单次、批量组件各自使用本地 Form/useState，草稿、结果和选中标签都会随卸载丢失。
- 两种评估共用 FlagInputs，其中 Flag Key 目前是普通 Input，已有列表 API 支持环境和分页，可复用真实 Go 数据。
- FlagRepo.Delete 已存在，rules/histories 的外键均 ON DELETE CASCADE；没有对应 service、DELETE 路由、客户端方法或列表按钮。
- 原设计 D7 不提供 Flag 删除。此次用户的新要求覆盖该取舍；历史版本文档保留其当时事实，当前 README 要更新。

## 方案比较与推荐

状态保留可采用三种方式：保持控制台组件实例、将全部状态迁到全局 Context、序列化到 sessionStorage。推荐保持组件实例：覆盖表单、JSON、评估结果、错误、标签和表格展开/分页，改动较小，也不额外持久保存用户属性。全局状态需要迁移各组件内部状态；sessionStorage 主要解决刷新恢复，超出此次页面切换需求。

Flag 删除可采用直接删除或软删除。推荐直接删除并使用现有数据库级联：不改已有数据模型和唯一约束，删除后同环境 Key 可重新创建。软删除可保留归档历史和恢复能力，但需要新增字段、迁移、查询过滤和唯一约束策略，此次不采用。

## 拟实施行为

### 1. 导航时保留控制台状态

- 首次进入控制台时创建组件，此后页面导航仅隐藏/显示同一组件实例。
- 单次和批量输入、环境、JSON 草稿、评估结果与轨迹、错误提示、选中的标签、批量表格状态均保留。
- 返回时不自动发起新的评估；结果仍标明当次提交的 Key、环境和评估时间，避免将旧结果误认为当前数据库配置。
- 本次范围是应用内路由切换。手动刷新、关闭页面后仍从默认初始状态开始。

### 2. Flag Key 可输入也可选择

- 两种评估共用可编辑的 AutoComplete。选项来源为自己实现的 Go 列表 API，按当前环境加载，包含启用和停用 Flag。
- 选项展示 Key、名称、启用状态；支持搜索匹配，也允许输入列表中没有的自定义 Key。
- 按现有 page_size 上限分页加载完整候选，避免只有第一页的 Key 可选。
- 环境变化或再次聚焦时刷新候选；取消过时请求，防止迟到结果把新环境的列表覆盖。切换环境保留用户填写的 Key，不擅自替换。
- 加载、空候选和获取失败有明确提示；失败可再次聚焦重试，自定义输入仍可使用。删除或新增后再次打开候选获取最新数据。

### 3. 列表删除整个 Flag

- 新增 DELETE /api/v1/flags/:id：合法现存资源返回204；非法 UUID 返回400；不存在或已删除返回404 FLAG_NOT_FOUND。
- 在 service 事务边界内删除，通过现有外键级联一并删除其规则和操作历史。失败时全部回滚，其他环境同 Key 的 Flag 不受影响。
- 列表操作区新增红色删除入口，二次确认明确显示 Key、环境以及“相关规则与操作历史一并删除，无法撤销”。
- 请求期间禁用该行的重复删除及启停操作；失败保留行并给出错误反馈；成功提示并刷新列表。当前页最后一行删除后回退到合法页，保留筛选条件。
- 删除后详情/历史/评估均按现有资源不存在契约反馈。同环境同 Key 可重新新建，新的 UUID 与历史独立。
- 本次不提供回收站、撤销或已删除 Flag 的审计浏览，不自动删除用户现有 Flag 或演示 seed。
